## 1. What this project is

**SpeakFlow AI** — a children's reading-fluency platform (hackathon project). Two roles, fully implemented with auth:

- **Teacher** (`teacher` / `speakflow123`): Teacher Hub, Students (real roster + CRUD), Reading Sessions, Pipeline Monitor, Practice Center, Reports, Progress Tracker, Settings (API keys, account approvals, sync)
- **Student** (self-signup → teacher approval): Dashboard (classic reading engine), Story Mode (gamified checkpoint reader), My Progress (merges classic + story reads), Practice Center (personalized), **My Settings** (`/settings` renders a student version: profile, reading preferences, change password, privacy note — teacher console is role-gated on the same route)

Two pipeline generations coexist **by design** (owner's decision — do NOT delete Gen-1):
- **Gen-1 "classic engine"** at `/dashboard` + `/pipeline/run`: **Groq Whisper online (with local Whisper auto-fallback) + librosa acoustics** → **5 Gemini Flash-Lite agents** (measured: full pipeline ~19s vs ~86s with the old `gemma-4-31b-it`; single call 1.1s vs 32.3s) → single JSON. **Teacher-selectable in Settings → "Reading AI Engine"**: `STT_MODE` (auto/groq/local) and `GEN1_AGENT_MODEL` (auto→Flash-Lite / flash-lite / gemma), persisted to `.env` and applied live. Student-only page (teachers are redirected to /teacher). The response now includes `words_spoken` (per-word timing + STT confidence) — the classic dashboard's transcript is tappable with the same pronunciation popover as Story Mode (`/api/v1/words/tip`). The phonetic agent returns `struggling_phonemes` as `{label, words}` objects so "Sounds to Practice" chips show which words they target (frontend heuristically derives words for legacy string shapes). Practice generation is **adaptive**: the practice agent receives `recent_accuracy`/`recent_wpm`/`sessions_practiced` and follows a difficulty ladder (≥90 → all hard mastery; 70-89 → medium/hard on flagged sounds; <70 → short easy wins on flagged words); the fallback net is tiered too (story sentences containing flagged words for weak reads, tongue-twisters for strong reads). **Warm-up sentences are dynamic**: `GET /pipeline/sentences?difficulty=easy|medium|hard` generates a fresh set of 5 via the agent model (static same-difficulty banks offline); the classic dashboard loads a fresh set on open and has a difficulty selector + shuffle button (no more fixed stock five). Dashboard card heights are content-driven (fixed `h-80`/`h-[400px]` wrappers removed — they caused the clipping/overlap issues). **TTS everywhere kid-facing** via browser `speechSynthesis` (`lib/speech.ts`, no API): play button on the classic target sentence + every Targeted Practice sentence, "Hear this word" in both word popovers (classic + Story Mode), and "Hear it first" on the Story Mode checkpoint sentence — language-aware (`ur-PK` voice used for Urdu when the device has one). The Gen-1 classic recording now honors the student's preferred mic and actually enforces its displayed 30s cap (auto-stop).

**Per-word scoring is measurement-driven in BOTH engines (fixed after the "Jesus/land" report):** the classic dashboard's transcript used to be colored by the *agents'* word list — a genuinely wrong word (land for lawn) displayed as correct if the agent didn't mention it. Now `/pipeline/run` runs the same alignment scorer as Story Mode (`align_words` + `score_word`) and returns per-word results; the classic transcript colors green/amber/red from measurement, skipped words show struck-through red, and **inserted words that were never printed are penalized** ("Jesus" mid-sentence → red "extra word", counted against accuracy in both engines — `align_words` collects `extra_words`, `build_signal` and the classic path score them).

**STT literalness (fixed after the "jump→jumped" report):** Whisper's decoder smooths toward fluent text (its grammar prior resolves "jump over" → "jumped" because the /t/ is acoustically near-silent). Mitigations now in place: (1) both STT paths condition on a **verbatim-dictation prompt** (Groq `prompt` param + `temperature=0`; faster-whisper `beam_size=1, temperature=0, condition_on_previous_text=False, initial_prompt`; openai-whisper equivalents) — English and Urdu variants in `LITERAL_PROMPTS` (services/stt.py); (2) **morphology-aware scoring** (services/acoustic.py `_morphology_error`): when the transcript differs from the printed word only by an inflection ending (jump/jumped, sleep/sleeping, run/running), the word is scored **incorrect with an honest label** — `missing -ed`, `added -ing` — instead of passing or a generic "unclear". **Empirically verified (Windows TTS A/B test):** Groq whisper-large-v3 at temperature 0 transcribes chase/chased and sleep/sleeping correctly literally in every prompt configuration, on clean WAV *and* on 32kbps opus (browser-quality) audio — the STT layer does not autocorrect when the audio carries the distinction. Residual corrections in live sessions therefore come from the microphone chain; both recorder contexts now request `noiseSuppression: false` (Chrome's suppressor smears quiet word endings) and record at `audioBitsPerSecond: 128000`.

**Practice Center tracks real progress (verified end-to-end 2026-09-06):** classic-engine flagged words now flow into the student's practice library alongside Story Mode errors (exercises carry `sources` + `trend`), and the endpoint computes progress trends by splitting the student's reads into earlier vs recent halves: per-sound `improving`/`worsening`/`new` and `conquered_words` (missed earlier, read correctly recently). The Practice Center page shows a "Your Progress" strip (Getting better / New this week / Words conquered) plus trend arrows on each exercise card. Gen-1 `sessions` rows carry a `language` column so My Progress shows which language each classic read was in (اردو badge). Full student-flow verification (temp student: story reads with mistakes → flawless retakes → Urdu classic read) passed 20/20 against the live server: personal scoping, both engines merged, trends, conquered words, and complete cleanup.

**Urdu is a first-class language on the classic dashboard** (2026-09-06 night): a top-right **EN | اردو** toggle (Topbar, persisted to the shared `storyLanguage` pref — the Story Mode map toggle writes the same pref). Flipping to Urdu switches everything: `/pipeline/sentences` generates Urdu sentences (Urdu fallback banks per difficulty), `/pipeline/run` passes `language` → STT in Urdu, the phonetic agent labels Urdu-letter confusions (د_vs_ڈ …), the practice agent writes Urdu sentences + encouragement, RTL + Nastaliq rendering on the sentence/transcript/popovers, and TTS uses the Urdu voice when the device has one. Verified live: Urdu hard sentences from Gemini; full Urdu mock run returned د_vs_ڈ on لومڑ with Urdu practice targeting حروف د/ڈ. Known limits: offline local Whisper is weak at Urdu (use the online Groq path), device Urdu TTS voices vary, and Urdu reference vectors still need calibration like English.
- **Gen-2 v2 layer** at `/api/v1/*` + Story Mode: Groq Whisper (online, live key) → local Whisper fallback (faster-whisper INT8 if installed) → librosa acoustics (pitch/ZCR/energy/LPC formants) + reference-vector dictionary → composite word scores → Gemini (`gemini-3.5-flash-lite`) feedback + hesitation judgment, template fallback. Two-phase response (Phase 1 immediate, Phase 2 async via WebSocket `/ws/sessions/{id}` + polling fallback). **Phase-1 words now carry `spoken`** (what the child actually said) and the Story Mode results screen has a **tap-a-word pronunciation popover**: `GET /api/v1/words/tip` (letter tiles + syllable split + Gemini coach tip, cached in the `word_tips` table — one API call per word ever).

**Bug fixed 2026-09-06 evening:** `stt.local_whisper` unpacked the transcribe result dict as a tuple — every local-fallback STT call produced garbage/crashed. Fixed and verified with a real forced-local run. The Gen-1 agents also moved from `generate_content_async` (very slow under uvicorn) to the `asyncio.to_thread(sync)` pattern v2 uses.
